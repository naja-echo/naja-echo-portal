# Implementation Plan: Org Blueprint Listing

**Branch**: `027-org-blueprint-listing` | **Date**: 2026-07-23 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/027-org-blueprint-listing/spec.md`

## Summary

Add an Org Blueprint Listing feature that shows all unique blueprints held by any member of the authenticated user's organization, with a read-only detail panel displaying ingredient information and a list of org members who own the blueprint. The feature mirrors the Personal Blueprint listing and detail panel but scopes queries to the entire org rather than a single user, and replaces the Remove button with an Owners section.

No EF Core migration is required — all queries use existing tables.

## Technical Context

**Language/Version**: C# on .NET 10 (backend) / TypeScript with React (frontend)

**Primary Dependencies**: ASP.NET Core Web API, EF Core + Npgsql, TanStack Query, shadcn/ui Sheet component (already in repo)

**Storage**: PostgreSQL — existing tables: `user_blueprints`, `organization_memberships`, `AspNetUsers`, `sc.blueprints`, `sc.blueprint_tiers`, `sc.blueprint_slot_options`

**Testing**: xUnit + FluentAssertions + WebApplicationFactory (backend); Vitest + React Testing Library + MSW (frontend)

**Target Platform**: Web (browser SPA + .NET API)

**Project Type**: Full-stack web application (modular monolith)

**Performance Goals**: Standard web — listing and detail load without noticeable delay for org sizes up to several hundred blueprints

**Constraints**: Read-only feature; no mutations. No EF Core migration needed.

**Scale/Scope**: Single org (current Naja Echo org); all authenticated users are org members

## Key Design Decisions

### Org scoping via OrganizationMembership

Both new repository methods accept `Guid userId` and internally resolve the user's current `organization_id` via a sub-query on `organization_memberships WHERE is_current = true AND user_id = {userId}`. This avoids passing orgId through the entire call stack while keeping the SQL self-contained.

### SQL for GetListAsync

```sql
SELECT
  b.id            AS blueprint_id,
  b.product_name,
  b.type,
  COUNT(DISTINCT bso.slot_index)::int AS ingredient_count
FROM organization_memberships om
JOIN user_blueprints ub ON ub.user_id = om.user_id
JOIN sc.blueprints b ON b.id = ub.blueprint_id
LEFT JOIN sc.blueprint_tiers bt
       ON bt.blueprint_id = b.id AND bt.tier_index = 0
LEFT JOIN sc.blueprint_slot_options bso ON bso.tier_id = bt.id
WHERE om.organization_id = (
    SELECT organization_id FROM organization_memberships
    WHERE user_id = {userId} AND is_current = true
    LIMIT 1
)
AND om.is_current = true
GROUP BY b.id, b.product_name, b.type
ORDER BY b.product_name NULLS LAST, b.id
```

### SQL for GetDetailAsync (header)

```sql
SELECT
  b.id            AS blueprint_id,
  b.product_name,
  b.type,
  bt.craft_time_seconds,
  COUNT(DISTINCT bso.slot_index)::int AS ingredient_count
FROM sc.blueprints b
JOIN user_blueprints ub ON ub.blueprint_id = b.id
JOIN organization_memberships om
     ON om.user_id = ub.user_id
    AND om.is_current = true
    AND om.organization_id = (
          SELECT organization_id FROM organization_memberships
          WHERE user_id = {userId} AND is_current = true LIMIT 1
        )
LEFT JOIN sc.blueprint_tiers bt
       ON bt.blueprint_id = b.id AND bt.tier_index = 0
LEFT JOIN sc.blueprint_slot_options bso ON bso.tier_id = bt.id
WHERE b.id = {blueprintId}
GROUP BY b.id, b.product_name, b.type, bt.craft_time_seconds
```

Returns `null` if no rows (blueprint not held by any org member).

### SQL for slot options (reused from personal detail)

```sql
SELECT bso.slot_index, bso.slot_name, bso.option_index,
       bso.material_name, bso.kind, bso.quantity
FROM sc.blueprint_slot_options bso
JOIN sc.blueprint_tiers bt ON bt.id = bso.tier_id
WHERE bt.blueprint_id = {blueprintId} AND bt.tier_index = 0
ORDER BY bso.slot_index, bso.option_index
```

### SQL for owners

```sql
SELECT
  u."Id"           AS user_id,
  CASE WHEN u.display_name <> '' THEN u.display_name
       ELSE u.discord_username END AS display_name
FROM user_blueprints ub
JOIN "AspNetUsers" u ON u."Id" = ub.user_id
JOIN organization_memberships om
     ON om.user_id = ub.user_id
    AND om.is_current = true
    AND om.organization_id = (
          SELECT organization_id FROM organization_memberships
          WHERE user_id = {userId} AND is_current = true LIMIT 1
        )
WHERE ub.blueprint_id = {blueprintId}
ORDER BY display_name
```

### OrgBlueprintDetailPanel

Mirrors `BlueprintDetailPanel.tsx` with these differences:
- No `useRemoveMyBlueprint` hook; no isConfirming state; no footer with Remove button
- Calls `useGetOrgBlueprintDetail(blueprintId)` instead of `useGetBlueprintDetail`
- Adds an Owners section below the ingredient list: heading "Who has this blueprint?" + list of `owner.displayName`; empty state: "No members currently have this blueprint."
