# Implementation Plan: Blueprint Detail Panel

**Branch**: `026-blueprint-detail-panel` | **Date**: 2026-07-23 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/026-blueprint-detail-panel/spec.md`

## Summary

Add a slide-over detail panel to the personal blueprints page. Clicking a blueprint row opens the panel from the right, showing the blueprint name, Type/Craft Time/Ingredient Count summary, a two-level ingredient list, and a Remove button with inline confirmation. Also renames the frontend route from `/blueprints/mine` to `/blueprints/personal` (with redirect) and adds two new backend API endpoints: `GET /api/blueprints/mine/{blueprintId}` and `DELETE /api/blueprints/mine/{blueprintId}`.

No EF Core migration is required — all data is read from existing `sc`-schema tables, and the remove operation deletes an existing `user_blueprints` row.

## Technical Context

**Language/Version**: C# on .NET 8 (backend); TypeScript / React (frontend)

**Primary Dependencies**:
- Backend: ASP.NET Core minimal APIs, EF Core 8, Npgsql, FluentValidation
- Frontend: React, TanStack Query, shadcn/ui `Sheet` component (already in repo at `components/ui/sheet.tsx`), Lucide React

**Storage**: PostgreSQL 16 — reads from `sc.blueprint_tiers`, `sc.blueprint_slot_options`; deletes from `user_blueprints`

**Testing**:
- Backend: xUnit, FluentAssertions, WebApplicationFactory + fake repositories
- Frontend: Vitest, React Testing Library, MSW

**Target Platform**: Web (browser SPA + ASP.NET Core API)

**Performance Goals**: Detail panel load < 1s on standard connection (SC-001)

**Constraints**: No new EF Core migration required. No new npm dependencies required. Frontend bundle impact must be negligible (Sheet component already present).

**Scale/Scope**: Small org (~50 users, hundreds of blueprints per user). No pagination needed for ingredient list.

## Key Design Decisions

### Backend: GetBlueprintDetailHandler

1. Verify user owns the blueprint: query `user_blueprints` for `(user_id, blueprint_id)` — return 404 if not found.
2. Query `sc.blueprints` for `product_name`, `type`.
3. Query `sc.blueprint_tiers` for `craft_time_seconds` at `tier_index = 0`.
4. Query `sc.blueprint_slot_options` WHERE `tier_id = <tier0.id>`, ORDER BY `slot_index`, `option_index`.
5. Group in application code: rows with same `slot_index` → one `BlueprintSlotDto`.
6. Return `BlueprintDetailDto`.

All raw SQL queries follow the existing `SqlQuery<T>` pattern in `UserBlueprintRepository`.

### Backend: RemoveMyBlueprintHandler

1. Verify user owns the blueprint: find `UserBlueprint` entity by `(user_id, blueprint_id)`.
2. If not found → throw domain exception → 404.
3. `DbContext.UserBlueprints.Remove(entity)` + `SaveChangesAsync`.

### Frontend: BlueprintDetailPanel

- Built on `Sheet` with `side="right"` from `components/ui/sheet.tsx`.
- Opens when `selectedBlueprintId` state is non-null in `MyBlueprintsPage`.
- Fetches detail via `useGetBlueprintDetail(blueprintId)` — TanStack Query with key `['blueprints', 'detail', blueprintId]`.
- Craft time formatted: `Math.floor(s/60) + 'm ' + (s%60) + 's'`; if null → "—".
- Remove button triggers `useRemoveMyBlueprint()` mutation:
  - First click → shows inline confirmation.
  - Confirm click → fires DELETE, on success: invalidates `['blueprints', 'mine']`, clears `selectedBlueprintId` (closes panel).
  - Cancel click → resets to normal footer.

### Frontend: Route Rename

In `AppRouter.tsx`:
```
<Route path="/blueprints/personal" element={<MyBlueprintsPage />} />
<Route path="/blueprints/mine" element={<Navigate to="/blueprints/personal" replace />} />
```

In `navItems.ts`: change `path` to `/blueprints/personal`.
